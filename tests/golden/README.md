# Golden files

Two files, one fixture: `examples/configuration.nix`, which is upstream's own
example, byte-identical to `Plommonsorbet/nix-mikrotik` at `c6a1ce8`.

| file | what produced it | what it gates |
|---|---|---|
| `legacy-upstream.rsc` | **upstream's** `mikrotik.nix` (sha256 `dacd23df…`) | a cross-implementation check: this renderer may not drift from upstream's semantics |
| `legacy.rsc` | this repository's renderer | a self-snapshot: `mikrotikConfigurations.legacy.script` must not change, byte for byte |

`tests/render.nix` uses both. Neither is a render compared against itself:
`legacy-upstream.rsc` is produced by code that lives in this repository only as
upstream's unmodified `mikrotik.nix`, and `legacy.rsc` pins our own bytes so a
refactor cannot move them unnoticed.

## The four deviations

This renderer is **not** byte-identical to upstream's, and an earlier revision of
the README said it was. Upstream's own output for this fixture hashes
`sha256 5b2a461e…` (1837 bytes); ours hashes `sha256 06a6a993…` (1884 bytes).
Every `add`/`set` line is the same, in the same order. The differences are four
deliberate ones:

1. **a header line** — `# Generated by nix-mikrotik -- do not edit.`
2. **`/system identity` comes first, with its value quoted** — upstream emits the
   section in alphabetical position (`/system clock`, `/system identity`, `/tool
   …`) as `set name=nidas`; here the identity is an option, so it is rendered at
   the top as `set name="nidas"`.
3. **a final newline** — upstream's output ends without one.
4. **section order is pinned where a section has to come first**
   (`sectionOrder ++ alphabetical`), which for this fixture is upstream's order
   already. That is why the rest of the file can be compared directly.

`tests/render.nix` asserts (1), (2) and (3) by name, drops what they account for
(`/system identity` and its `set` line, and comment lines) from both sides, and
diffs the rest. A drift in any other line, or in the order of the lines, fails
the diff.

## Regenerating upstream's golden

From a pristine upstream checkout, evaluated with the nixpkgs this flake pins:

```sh
git clone https://github.com/Plommonsorbet/nix-mikrotik upstream
cd upstream && git checkout c6a1ce8        # mikrotik.nix sha256 dacd23df…
NIXPKGS=$(nix eval --impure --raw --expr \
  'toString (builtins.getFlake "/abs/path/to/nix-mikrotik").inputs.nixpkgs.outPath')
NIX_PATH="nixpkgs=$NIXPKGS" nix-build ./mikrotik.nix
cp result/router-config.rsc <path>/tests/golden/legacy-upstream.rsc
```

Commit the file exactly as it comes out, **including the missing trailing
newline** — that is deviation 3, and `tests/render.nix` asserts it is still
missing, so a fixture that gained one by accident is a failure rather than a
silent normalisation. If upstream's generator changes, this file, the deviations
above and the assertions in `tests/render.nix` change in one commit.
